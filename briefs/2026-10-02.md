## What I found

**The honest version of this feature is mostly a refusal.** I went in expecting to pick metrics and ended up computing how many events each one needs before it says anything. At a 5% cold-application response rate, detecting a jump to 15% needs 141 applications in each arm — 282 total. A seeker who gets one interview per ~40 applications ([aggregate commentary, weakly sourced](https://resutrack.com/blog/how-many-job-applications-to-get-interview-2026) — every number I found on this traces back to unnamed "recent studies", so §10 does not cite it) is not reaching that in a season. **Hoshi can never A/B test its own application funnel for one user.** Not slowly. At all.

That turns into the section's spine rather than a caveat. The warm path is the only stretch with a base rate high enough for one person's numbers to move — §1 already puts it ten times higher — so the metric set leans toward conversations for a second reason independent of the thesis. And the top metric is **person-attached rate**: a proportion of Dhwani's own behaviour, not the market's response, so it moves the same week and it measures whether she is running the thesis or just agreeing with it.

The honesty rules are where I spent the rest of it, because "do not claim causality without enough data" was a sentiment and not a rule. Now: no percentage under n=10, every rate shown with its 95% Wilson interval in the same type size, no comparative language unless two intervals are disjoint, and insufficient-data states give the shortfall as a number — "14 more sends before this rate means anything" — rather than a greyed-out zero. Six replies from twenty sends is `30% (15–52%)`, and that width is the whole point.

One thing I had to concede: B-04 was supposed to make §9's 20-of-100 connection weight falsifiable, and it cannot. Four tiers across one season's applications leaves each one far under 141. §10.4 records the two weaker tests it gets instead — a behavioural one available now, and an outcome one that needs pooled users, i.e. Q1 and Q3 — so a future run can't quietly claim the tag was retired.

The script behind §10.1 and §10.3, so the numbers can be rechecked rather than trusted. Nothing to apply to the codebase; this is verification only:

```python
import math

def n_per_arm(p1, p2, z_a=1.959963985, z_b=0.8416212336):
    """Two-sided two-proportion test, 80% power at alpha=0.05."""
    pbar = (p1 + p2) / 2
    num = (z_a * math.sqrt(2 * pbar * (1 - pbar))
           + z_b * math.sqrt(p1 * (1 - p1) + p2 * (1 - p2))) ** 2
    return math.ceil(num / (p2 - p1) ** 2)

def wilson(k, n, z=1.959963985):
    p = k / n
    d = 1 + z * z / n
    c = (p + z * z / (2 * n)) / d
    h = z * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n)) / d
    return max(0.0, c - h), min(1.0, c + h)

print(n_per_arm(0.05, 0.10))   # 435
print(n_per_arm(0.05, 0.15))   # 141
print(n_per_arm(0.25, 0.50))   # 58
print(wilson(6, 20))           # (0.145, 0.519)
```
