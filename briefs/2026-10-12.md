## What I found

The harvesting route is free, and that is the whole reason it is rule 1. Hoshi already fingerprints nine ATS vendors by URL to decide whether a page is a job page (§4), and a hosted board URL carries the board handle in its path — `job-boards.greenhouse.io/{token}`, `jobs.lever.co/{site}`, `jobs.ashbyhq.com/{name}`. So the parse that classifies the page also yields the handle, with no new permission, no second read, and no new code path. Opening one job at a company subscribes the whole board. That is a better acquisition story than asking you to paste URLs, and it is the kind of thing only a browser extension can do — Jobright cannot watch a board it has not already indexed.

The failure case is sharper than I expected, and it is Greenhouse's own documentation that makes it concrete. Companies are told to paste a script tag and *"replace 'bcg' with your job board token"*, and to set the Job Board URL setting to *"the base URL of the page your job board is embedded on"* — meaning their own careers page, not a Greenhouse URL ([Greenhouse support](https://support.greenhouse.io/hc/en-us/articles/46365908766875-Embed-a-Greenhouse-job-board-on-your-career-site)). On an embedded board the handle lives in page JavaScript and never appears in the URL, so rule 1 returns nothing. The tempting fix is to read the script tag. §8.7 forbids it twice over: a careers page is out of scope unless granted (Principle 4), and lifting a token out of page JS is the inference §8.4's provenance contract exists to prevent. Those boards resolve by paste or stay person-only — which is why person-only is a named state with a visible label rather than a silent zero.

One assumption I could not close, now tagged and folded into B-11: that the handle in a hosted board URL is byte-identical to the handle the API path takes. It follows from §8.2's endpoint shapes but no provider states it, and three of the four provider docs (Greenhouse, Lever, Ashby) refused to open from this sandbox today — the permission prompt went unanswered, as the 10-04 constraint warns. So B-11's `curl` should now use a handle lifted from a real board URL: if it returns that board's jobs, the CORS question and the equivalence question close in the same request.
