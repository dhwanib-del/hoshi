## What I found

`mayMarkApplied` is the function Principle 1 is named after — the last thing the application flow writes. It wrote `weightsVersion: '2026-09-29'` as a string literal, while `scoreJob` three lines upstream was scoring against the table you set on 11-03. So every application you have marked submitted since Monday carries a `totalScore` from one scale and a label saying it came from another.

The interesting part is that **yesterday's run could not have caught this.** It derived every scored figure from the table and wrote eight CI assertions to end exactly this class of defect. But `weightsVersion` is the one field on that row that nothing in the product reads — it is written for a segmentation that does not exist yet — and a test can only assert over a value something consumes. The literal was invisible to the test written to prevent it.

And it was urgent rather than tidy, which is the second thing worth keeping. The event log is append-only. A display bug is fixed by the next release; a row written wrong is wrong for ever, and those rows are the only record of this season. That is why the version fix went first and B-26 — which is a labelling defect in the same area, and arguably more visible to you — is filed rather than fixed.

The fix is invariant (13)'s shape moved from a quantity to an identity: derive the value from the thing it describes, carry it with that thing, and refuse the write when it is missing instead of defaulting. The version is now `aut20-con15-eli20-fre10-loc5-por5-rol25` — ugly, readable years later, and impossible to leave behind.
