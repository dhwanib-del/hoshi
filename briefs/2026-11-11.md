## What I found

I pointed the audit rule at the document's **clocks**: of each one, who can restart it? The tier belongs to the **contact**, the log's grain is the **thread** — pinned there on 10-21 precisely because a contacts-based denominator is not a reply rate — so *no reply within 21 days of the thread's `outreach` row* had as many start times as you have threads with that person, and nothing said which counted. The code took the most recent.

Two things I ran rather than argued. A thread opened 40 days ago and never answered scored C1; adding one send about a second opening put the same contact back at **C2**, so four points came back because **you** sent something. And the decaying row keyed off the same value, so the one surface that would have told you the path was cold went quiet on the same keystroke — worse than the three-day window it reads as, because following up on day 20 moved the warning to day 38, meaning a thread you had followed up never warned inside its own life at all.

One more unanswered message is more evidence the path is cold, not less. The reusable half: **where a rule is ambiguous and one reading flatters, assume the implementation took the flattering one** — that is the branch nobody notices. So an ambiguity in a scoring rule deserves the same urgency as a defect.
